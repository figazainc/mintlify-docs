MCP servers give Figaza's agents tools beyond the ones built into the app. If a service you use publishes an MCP server, connecting it lets the assistant use those tools directly in your conversations.

Where an [integration](/integrations/overview) pulls *data* into your project on a schedule, an MCP server gives the assistant the ability to *act* against another system during a turn.

Manage them in **Settings → AI**, under **MCP servers**.

## Add a server

<Steps>
  <Step title="Choose Add MCP Server">
    The dialog is titled **Remote MCP Servers**.
  </Step>
  <Step title="Paste a config">
    Paste JSON in either of the two formats below. The editor flags syntax errors — **Fix JSON syntax errors before saving** — before it lets you save.
  </Step>
  <Step title="Save">
    For local servers, Figaza fetches what it needs the first time. You will see **Downloading dependencies…** and then **Dependencies ready**.
  </Step>
</Steps>

## The config format

Configs are the same shape used by other MCP clients, so a config you already have for another editor generally pastes in as-is.

Everything lives under a top-level `mcpServers` key. The object keys are the server names:

```json
{
  "mcpServers": {
    "linear": {
      "url": "https://mcp.linear.app/mcp",
      "enabled": true
    }
  }
}
```

An array is also accepted, in which case each entry needs its own `name`:

```json
{
  "mcpServers": [
    { "name": "linear", "url": "https://mcp.linear.app/mcp" }
  ]
}
```

Server names must be unique — a duplicate name is rejected rather than silently overwriting.

### Remote servers

A server with a `url` is remote.

| Field | Required | Notes |
| --- | --- | --- |
| `url` | Yes | The server endpoint. Must not be empty |
| `type` | No | `"http"` or `"sse"`. Inferred from the URL when omitted — a path ending in `/sse` is treated as SSE, everything else as HTTP |
| `headers` | No | An object of string values, for example an authorization header |
| `enabled` | No | Boolean, defaults to `true` |

With headers:

```json
{
  "mcpServers": {
    "acme": {
      "type": "http",
      "url": "https://mcp.acme.com/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN"
      },
      "enabled": true
    }
  }
}
```

<Warning>
  A token in a `headers` block is stored as part of the server configuration, not as a [stored credential](/integrations/overview#stored-credentials). Prefer a server that handles its own sign-in where one exists, and remember that rotating a pasted token means editing this config.
</Warning>

### Local servers

A server with a `command` runs as a local process.

| Field | Required | Notes |
| --- | --- | --- |
| `command` | Yes | The program to run, for example `npx` |
| `args` | No | An array of strings |
| `env` | No | An object of string environment values |
| `enabled` | No | Boolean, defaults to `true` |

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"]
    }
  }
}
```

`npx`-style configs work without you installing anything — Figaza fetches what it needs the first time you use one. Any other command runs as written, so a server already installed on your machine can be launched by its full path.

### What is not accepted

A config that is nearly right is rejected rather than half-connected, and the error names the server and the field at fault.

| Config | Why |
| --- | --- |
| An `auth` block | Not supported |
| `command`, `args`, or `env` on a remote server | Those belong to local servers only |
| `type: "stdio"` with no `command` | A local server needs something to run |
| Any field not listed above | Unrecognised fields are rejected, not ignored |
| Two servers with the same name | Names must be unique |
| `headers` or `env` values that are not text | Both take text values only |

## Server status

| Status | Meaning |
| --- | --- |
| **Connected** | Working, and its tools are available to agents |
| **Not connected** | Configured but not currently connected |
| **Disabled** | Turned off by you |
| **Error** | Something is wrong with the configuration or the server |

**Tools found** lists what each server exposes, with each tool's description. If a server reports no tools yet, you get **No tools discovered yet**.

**Refresh** re-reads a server's tool list — what you want after the server is updated on its end.

## Managing servers

- **Edit** changes the configuration
- **Disable** and **Enable** turn a server off and back on without removing it
- **Remove** deletes it

Disabling is the better move when you are diagnosing whether a server is causing a problem: the config survives, so re-enabling is one click rather than a re-paste.

## How agents use MCP tools

Once a server is connected, its tools join Figaza's own for the assistant to call. The assistant is told which MCP services are configured, and reaches for them when they fit the task.

Each tool stays tied to the server it came from, so two servers offering similarly named tools do not conflict.

MCP tool calls appear in the chat transcript like any other tool call, so you can see when an external system was touched.

<Warning>
  MCP tools reach outside your project, and the review step that protects your documents does not apply to them. An MCP tool that can write to an external system will do so when the assistant judges it appropriate. Connect servers you trust, and prefer read-only servers where the choice exists.
</Warning>

---
title: "Integrations"
description: "Have the assistant build a live data pipeline from a tool Figaza has no connector for."
---

Integrations are autonomous data pipelines. They pull data from an external tool on a schedule and keep it available in your project — Linear issues, Jira sprint status, GitHub issues, and so on.

There is no connector catalogue to browse. You describe what you want in chat and the assistant builds it.

## Set one up

<Steps>
  <Step title="Ask">
    In chat, describe the pipeline you want:

    ```text
    Set up an integration that pulls our open Linear issues into this project every morning.
    ```
  </Step>
  <Step title="Answer a few questions">
    The assistant works out which service and which data, then researches that service's API to find the right endpoint and how it authenticates. It explains anything technical in plain terms before asking you about it.
  </Step>
  <Step title="Provide a credential, once">
    If it needs an API key or token, it tells you exactly where to find it in that tool — and then collects it through a secure prompt.

    <Warning>
      You will never be asked to paste a key into the chat, and the assistant will not ask again for a credential you have already stored. If something ever asks you to type a token into a chat message, that is not how this works.
    </Warning>
  </Step>
  <Step title="Confirm the schedule">
    Say how often you want the data refreshed — every hour, once a day at a particular time, or manually only — and confirm.
  </Step>
  <Step title="It installs and verifies">
    The assistant tests the connection, saves the integration, runs it live once, and reports back with a preview of what it fetched.
  </Step>
</Steps>

Your data then appears in the **Sources** panel under the integration's name.

## Managing integrations

Integrations are listed in **Settings → Integrations** and in the **Sources** panel. Each shows its **Last run** time and its number of **Runs**.

| Action | What it does |
| --- | --- |
| **Run now** | Fetches immediately, outside the schedule |
| **Pause** / **Resume** | Stops and restarts scheduled runs without losing the setup |
| **Delete integration** | Removes it permanently |

An integration that has not fetched anything yet shows **No data yet**. One that has never run shows **Never** as its last run.

## Stored credentials

**Settings → Integrations** also holds **Stored credentials** — the API keys and tokens your integrations have saved.

Values are never displayed, not even to you. You can **Replace value** or **Delete credential**, and that is the whole surface. A credential is shared by all integrations against the same service, so you enter a Linear key once no matter how many Linear pipelines you build.

## What is not supported

Services that require OAuth2 — the *Sign in with…* flow, common for Google and Salesforce — cannot be set up this way. They need a purpose-built connector, and the assistant will tell you so rather than trying and failing.

For those, use the built-in [Notion](/sources/notion) and [Google Drive](/sources/google-drive) connections.

API key and bearer token services are the ones this works for, which covers most developer-facing tools.
